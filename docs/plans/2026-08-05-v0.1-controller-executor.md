# v0.1 Journaled Controller Executor

## Objective

Turn a validated `controller-transport-plan` into a locally auditable
execution without changing the four v0.1 method-layer artifact contracts.

## Boundaries

- The executor writes only below the explicitly supplied project path.
- The default runtime root is `.ccpanes-method/v0.1/controller/executions`.
- CC-Panes credentials are read from the current process environment and are
  never written to a journal or response artifact.
- `D:\cc-pane`, user configuration, dependencies, Git history, remotes, UI,
  hooks, plugins, and profiles remain outside this implementation.

## Transport

The production driver uses MCP Streamable HTTP:

1. `POST /mcp` `initialize`;
2. `POST /mcp` `notifications/initialized`;
3. `POST /mcp` `tools/call`;
4. parse the final JSON-bearing SSE `data:` event;
5. unwrap JSON from MCP text content.

Endpoint and token come from `CC_PANES_API_BASE_URL` and
`CC_PANES_API_TOKEN`. An injected invoker is used by deterministic tests.

## Persistence

Each plan gets one deterministic execution directory:

```text
.ccpanes-method/v0.1/controller/executions/<planId>/
  journal.jsonl
  responses/
    step-001-attempt-001.json
  execution.lock
```

The journal is append-only JSON Lines. Every entry records the plan hash,
request hash, attempt number, normalized outcome, and response hash/path when
present. Full requests are not duplicated into the journal.

## Safety model

- Validate the plan and every journal entry before use.
- Reject a journal whose plan hash, plan id, execution id, or sequence differs.
- Hold an exclusive file handle for the execution lifetime.
- Verify TaskBinding id, session, role, status, and metadata hash immediately
  before an update.
- Re-read after every update and evaluate planner assertions.
- Retry transient read/update operations at most three times per invocation.
- Never automatically retry an ambiguous `launch_task` or
  `report_to_leader`.
- Skip a previously journaled successful mutation only when its request hash
  still matches.
- Treat partial/corrupt journal lines and response hash conflicts as
  `manual-review`.

## Modes

- `dry-run`: validate and describe; no transport call and no runtime mutation.
- `live`: execute through the production MCP driver or an explicitly injected
  test invoker.

## Acceptance

- successful bind/finish/handoff plans persist ordered evidence;
- transient reads retry and permanent failures do not;
- metadata drift blocks update;
- readback mismatch blocks advancement;
- replay skips a successful update and re-runs readback;
- non-idempotent ambiguity stops after one attempt;
- a read-only live MCP probe succeeds against the current CC-Panes endpoint;
- repository validation includes executor schemas, parser checks, and tests.
