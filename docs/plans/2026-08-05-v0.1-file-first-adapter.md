# v0.1 File-First Adapter Implementation Plan

> **Execution profile:** `codex-gpt55-heavy` is recommended because this plan adds a multi-command adapter, shared storage primitives, recovery behavior, fixtures, and cross-contract tests.

**Status:** Implemented and locally verified on 2026-08-05.

**Goal:** Implement a dependency-free local reference adapter that converts v0.1 method artifacts into CC-Panes launch/finish/handoff envelopes while keeping artifact files as the method-layer source of truth.

**Architecture:** Use PowerShell 7 for a repository-local adapter with four layers: command entry points, pure domain mapping, guarded artifact storage, and narrow CC-Panes JSON contracts. The local commands prepare and consume CC-Panes request/response envelopes; they do not modify CC-Panes core or directly own runtime transport.

**Tech stack:** PowerShell 7.6+, JSON Schema draft 2020-12, Python standard-library `json.tool`, Git CLI read-only inspection, SHA-256 from PowerShell/.NET.

**Confirmed design:** `docs/specs/2026-08-05-ccpanes-v0.1-file-first-adapter-design.md`

**Execution scope:**

- Work only in `D:\ccpanes-method-layer`.
- Keep `D:\cc-pane` as a read-only contract reference.
- Keep dependency installation, user-global configuration, Git commit/push/remote actions, UI, hooks, plugins, profiles, and CC-Panes database migrations outside this plan.
- Preserve the four v0.1 protocol schemas without changing their semantics.

## Command contracts

### `prepare-launch.ps1`

Inputs:

- `-TaskPath`
- `-CliTool`
- `-Profile`
- `-RuntimeKind`
- optional `-ProviderId`, `-ProviderSelection`, `-WorkspaceName`
- optional `-PaneId`, `-LayoutId`, `-LayoutName`, `-Placement`
- optional `-ResumeId`
- optional `-ArtifactRoot`

Output:

```json
{
  "operation": "prepare-launch",
  "attemptPath": "relative/path.json",
  "taskSha256": "HEX",
  "runId": "run-...",
  "launchTaskRequest": {
    "projectPath": "D:\\project",
    "prompt": "rendered prompt",
    "cliTool": "codex",
    "profileId": "PROFILE",
    "runtimeKind": "local"
  }
}
```

The command validates and writes a `prepared` attempt before returning the launch request.

### `bind-launch.ps1`

Inputs:

- `-AttemptPath`
- `-LaunchResponsePath`
- optional `-ExpectedAttemptSha256`

Output:

```json
{
  "operation": "bind-launch",
  "runPath": "relative/path.json",
  "runSha256": "HEX",
  "launchTaskId": "ORCHESTRATOR_TASK_ID",
  "taskBindingLookup": {
    "operation": "find_task_binding_by_session",
    "sessionId": "SESSION_ID"
  },
  "taskBindingPatch": {
    "metadata": {
      "methodLayer": {}
    }
  }
}
```

The command publishes `run.json`, updates the attempt to `bound`, and returns a session-based TaskBinding lookup plus the patch. The `launch_task.taskId` value remains an orchestrator launch identity and is not treated as `TaskBinding.id`.

### `finish-run.ps1`

Inputs:

- `-RunPath`
- `-TaskBindingPath`
- either `-EvidencePath` or `-SummaryOnly`
- optional `-ExpectedRunSha256`

Output:

```json
{
  "operation": "finish-run",
  "evidencePath": "relative/path.json",
  "evidenceSha256": "HEX",
  "runPath": "relative/path.json",
  "runSha256": "HEX",
  "taskBindingPatch": {},
  "leaderReport": {}
}
```

Complete evidence passes the method finish gate. Summary-only input creates truthful blocked/partial evidence with `not-run` or `blocked` checks and `needs-review` drift.

### `new-handoff.ps1`

Inputs:

- `-TaskPath`
- `-RunPath`
- `-EvidencePath`
- `-ContextPath`
- optional `-ExpectedTaskSha256`, `-ExpectedRunSha256`, `-ExpectedEvidenceSha256`

Output:

```json
{
  "operation": "new-handoff",
  "handoffPath": "relative/path.json",
  "handoffSha256": "HEX",
  "taskBindingPatch": {
    "metadata": {
      "methodLayer": {
        "latestHandoffPath": "relative/path.json"
      }
    }
  }
}
```

### `recover-launch.ps1`

Inputs:

- `-AttemptPath`
- optional `-LaunchResponsePath`
- optional `-TaskBindingPath`

Output:

- current attempt state
- known CC-Panes binding/session identities
- artifact consistency result
- one deterministic recovery action: `retry-launch`, `bind-response`, `repair-metadata`, `already-bound`, or `manual-review`

- evidence completed → run completed while TaskBinding patch preserves the supplied execution status/progress

## Fuse and stop conditions

- Stop if implementation needs a write in `D:\cc-pane`, user-global configuration, or another repository.
- Stop if a third-party dependency becomes necessary; reassess the dependency-free architecture first.
- Stop if current CC-Panes source contradicts the pinned request/response or TaskBinding contracts.
- Stop if adapter behavior requires changing the meaning of a v0.1 protocol field; open a protocol version review.
- Stop if path containment tests reveal a Windows reparse-point case that the chosen primitives do not safely classify.
- Stop after three repair cycles for the same failing root cause and report the evidence.
