# v0.1 Dry-Run Controller Transport Planner

## Objective

Make the five adapter envelopes locally consumable by a dependency-free
controller planner while preserving the no-live-runtime boundary.

## Inputs

- one validated adapter stdout envelope;
- optional fresh TaskBinding snapshot;
- optional original prepare envelope for `retry-launch`.

## Output

One `controller-transport-plan` document containing:

- source envelope identity;
- dry-run decision;
- correlation identities;
- ordered MCP request steps;
- leader notification disposition;
- readback assertions;
- audit notes.

## Implementation

- `controller/schemas/transport-plan.internal.schema.json`
- `scripts/controller/MethodLayer.Controller.psm1`
- `scripts/controller/plan-transport.ps1`
- `tests/controller/run.ps1`
- `tests/controller/fixtures/*.json`
- `controller/README.md`

9. merged update over 64 KiB enters `manual-review`;
10. retry recovery requires a matching prepare journal;
11. manual-review recovery emits no call;
12. bind-response recovery never relaunches;
13. repair recovery preserves metadata siblings;
14. already-bound recovery performs readback only.

## Excluded

- live MCP invocation;
- response persistence or journal implementation;
- retries against a running CC-Panes process;
- UI, plugin, hook, profile, or main-repository integration;
- commit, push, remote creation, or dependency installation.

## Acceptance

- planner output passes its internal schema;
- every mutation plan contains lookup, update, and readback ordering;
- no session or TaskBinding identity is inferred from launch task identity;
- metadata siblings are preserved;
- notification dispatch avoids the known terminal auto-notify duplication;
- all tests run from the repository validator;
- all files stay within `D:\ccpanes-method-layer`.
